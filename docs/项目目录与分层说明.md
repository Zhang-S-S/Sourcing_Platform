# 项目目录与分层说明

当前项目为 `Springboot_React`。后端按技术层组织目录；前端按页面、布局、业务状态和公共能力组织目录。

## 后端：Spring Boot 分层

源代码根目录：`backend/src/main/java/com/sourcing/`。

```text
com/sourcing/
├── SourcingApplication.java           Spring Boot 启动入口
├── controller/                        接口层：接收请求、返回结果
│   ├── AuthController.java            注册、两种登录、验证码、当前账号
│   ├── MexicoExportController.java    墨西哥搜索、分页、详情
│   └── VendorSourceController.java    数据源状态查询入口
├── service/                           业务层：处理业务规则
│   ├── AuthService.java               账号校验、重复检查、密码与登录处理
│   ├── MexicoExportService.java       查询组织、游标分页、异常处理
│   ├── VendorSourceService.java       数据源诊断结果与错误提示
│   ├── SmsCodeVerifier.java           短信验证码服务接口
│   └── impl/
│       └── FixedSmsCodeVerifier.java  本地固定验证码 123456 的实现
├── dao/                               数据访问层：执行 SQL
│   ├── UserDao.java                   读写本地 MySQL 账号表
│   ├── MexicoExportDao.java           只读查询甲方墨西哥出口表
│   └── VendorSourceDao.java           执行只读连接诊断查询
├── entity/                            数据对象
│   ├── User.java                      本地账号，包含密码散列
│   └── MexicoExportLead.java          一条墨西哥出口贸易记录
├── dto/                               前后端传输的数据对象
│   ├── request/                       接收的数据与参数校验
│   │   ├── RegisterRequest.java       注册参数
│   │   ├── PasswordRequest.java       密码登录参数
│   │   ├── PhoneRequest.java          手机验证码登录参数
│   │   ├── SmsRequest.java            验证码获取参数
│   │   └── MexicoSearch.java          墨西哥搜索条件及其校验
│   └── response/                      返回的数据
│       ├── UserResponse.java          可返回前端的账号字段，不含密码散列
│       └── ExportPageResponse.java    记录列表、下一页游标等分页信息
├── config/                            框架及连接配置
│   ├── SecurityConfig.java            接口权限、密码散列、会话与退出配置
│   └── VendorDataSourceConfig.java    甲方只读数据源及连接池配置
├── security/
│   └── AuthRateLimiter.java           请求频率限制
└── exception/                         统一异常处理
    ├── ApiException.java              带 HTTP 状态的业务异常
    └── GlobalExceptionHandler.java    将异常转换成前端可读的响应
```

DAO 对应原来的 Repository 数据访问类，仍使用 Spring JDBC 的 JdbcTemplate，并通过 `@Repository` 注解注册。类名以 Dao 结尾不会改变所用技术。

`entity` 中目前使用 Java record 表示数据对象，没有引入 JPA。`dto/request` 表达用户提交什么，`dto/response` 表达接口返回什么。账号对象与账号响应分开，避免把密码散列返回给前端。

调用顺序示例：

```text
注册：AuthController → AuthService → UserDao → 本地 MySQL
搜索：MexicoExportController → MexicoExportService → MexicoExportDao → 甲方 SQL Server
诊断：VendorSourceController → VendorSourceService → VendorSourceDao → 只读诊断 SQL
```

新增接口通常先在 `controller` 接收请求，再在 `service` 处理规则，数据库操作放入 `dao`。请求与返回对象按需要放进 `dto`。数据库连接和权限规则由 `config` 管理。

后端其余目录：

| 路径 | 用途 |
| --- | --- |
| `backend/src/main/resources/application.properties` | 8082 端口、会话、默认本地数据源等公共配置 |
| `backend/src/main/resources/schema.sql` | 本地账号表结构，仅用于本地 MySQL |
| `backend/data/mysql-local.properties` | 本地业务账号库连接凭据 |
| `backend/data/mysql-test.properties` | 本地测试库连接凭据 |
| `backend/data/vendor-local.properties` | 甲方 SQL Server 的本机连接配置 |
| `backend/src/test/java/com/sourcing/controller` | 接口集成测试 |
| `backend/src/test/java/com/sourcing/service` | 业务层测试 |
| `backend/src/test/java/com/sourcing/dao` | 查询、参数校验及 SQL 行为测试 |
| `backend/src/test/java/com/sourcing/support` | 测试数据构造工具 |
| `backend/src/test/resources/application-test.properties` | 隔离测试库与关闭甲方数据源的测试配置 |
| `backend/pom.xml` | Java 版本、依赖与 Maven 构建配置 |

业务账号库仍为 `sourcing_platform_react`，自动测试仍使用 `sourcing_platform_react_test`。整理目录不迁移业务数据，也不更改表结构。甲方 SQL 仍只读。

## 前端：React 目录

前端不套用 Java 的 DAO 分层。React 页面通过 HTTP 调用后端，数据库访问统一由后端处理。

```text
frontend/src/
├── main.jsx                           浏览器入口、加载样式
├── App.jsx                            应用入口，选择登录页或系统主界面
├── pages/                             页面展示
│   ├── auth/AuthPage.jsx              登录注册表单
│   └── suppliers/MexicoLeads.jsx      搜索、筛选、结果与详情
├── layouts/
│   └── Workspace.jsx                  侧栏、顶栏和主内容框架
├── components/
│   └── LegacyWorkspace.jsx            静态原型页面的 React 挂载容器
├── models/                            业务状态和交互逻辑
│   ├── authModel.js                   登录注册请求、验证码倒计时、会话管理
│   └── mexicoModel.js                 搜索条件、筛选、翻页、详情与缓存
├── hooks/                             将状态逻辑接入 React
│   ├── useAuth.js
│   ├── useMexicoModel.js
│   └── usePage.js
├── api/
│   └── client.js                      统一 HTTP 请求、Cookie、CSRF 与错误处理
├── router/
│   └── navigation.js                  地址、前进后退与页面状态恢复
├── store/
│   └── createStore.js                 内存状态与 React 订阅
├── utils/
│   └── ui.js                          样式处理辅助函数
├── styles/
│   ├── design.css                     保留的甲方原版样式
│   └── style.css                      加载、错误等补充状态样式
├── assets/
│   └── auth-illustration.png          登录注册配图
└── legacy/
    └── workspace.js                   收藏、对比等静态原型脚本
```

前端调用顺序示例：`AuthPage.jsx → authModel.js → api/client.js → 后端接口`。Hooks 负责订阅状态和生命周期，页面根据最新状态显示内容。

修改入口：

| 想调整什么 | 主要看哪里 |
| --- | --- |
| 登录注册表单 | `pages/auth/AuthPage.jsx` |
| 登录注册的前端流程 | `models/authModel.js` |
| 搜索页面显示内容 | `pages/suppliers/MexicoLeads.jsx` |
| 筛选、勾选、分页和详情加载 | `models/mexicoModel.js` |
| 前端统一请求处理 | `api/client.js` |
| 主界面导航和布局 | `layouts/Workspace.jsx` |
| 浏览器前进后退 | `router/navigation.js` |
| Java 登录业务规则 | `backend/.../service/AuthService.java` |
| 账号 SQL | `backend/.../dao/UserDao.java` |
| 墨西哥搜索 SQL 与字段映射 | `backend/.../dao/MexicoExportDao.java` |

## 原文件与新位置对应

| 原位置 / 名称 | 新位置 / 名称 |
| --- | --- |
| `auth/AuthController.java` | `controller/AuthController.java` |
| `auth/AuthService.java` | `service/AuthService.java` |
| `auth/UserRepository.java` | `dao/UserDao.java` |
| `suppliers/MexicoExportRepository.java` | `dao/MexicoExportDao.java` |
| `auth/ApiErrors.java` | `exception/GlobalExceptionHandler.java` |
| `UserRepository.User` | `entity/User.java` |
| `AuthController` 内的四个请求 record | `dto/request` 中独立的四个文件 |
| `AuthService.UserView` | `dto/response/UserResponse.java` |
| `MexicoExportService.Page` | `dto/response/ExportPageResponse.java` |
| `frontend/src/App.jsx` 内的登录注册表单 | `frontend/src/pages/auth/AuthPage.jsx` |
| `frontend/src/api.js` | `frontend/src/api/client.js` |
| `frontend/src/navigation.js` | `frontend/src/router/navigation.js` |
| `frontend/src/prototype/design.css` | `frontend/src/styles/design.css` |
| `frontend/src/prototype/workspace.js` | `frontend/src/legacy/workspace.js` |

接口 URL、JSON 字段、页面样式、验证码、端口和数据库配置沿用原值。原 `sourcing-platform` 项目保留原目录。

启动命令见项目根目录 README。已运行的后端需要在自己的终端按 Ctrl+C 后重新运行 `mvn spring-boot:run`，才能加载新包结构。前端开发服务器支持热更新；如页面未刷新，在浏览器中刷新即可。
