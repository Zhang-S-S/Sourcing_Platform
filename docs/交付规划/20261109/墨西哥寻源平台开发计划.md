# 墨西哥寻源平台开发计划

2026年11月9日至2027年1月29日

编制日期：2026-11-09　　版本：1.0　　人员条件：2至3人协作

## 1 交付基线与执行条件

本计划交付墨西哥寻源平台的完整 PRD，包含 P0 14项、P1 6项、P2 6项，共26项功能，并覆盖附录B的36个关键验收场景。保持甲方原版页面设计，完成寻源端、独立管理端、真实数据和平台业务的交互；原型演示不计为真实业务完成。

整体截止时间为2027-01-31之前。以2027-01-29星期五为正式验收交付日，1月30日仅作额外应急空间，不把最后一个周末作为常规开发期。功能齐套目标为1月15日，后两周集中完成联合验收、修复、部署、回滚检查和移交。

本期仅上线墨西哥寻源数据；C通道可包含向墨西哥供货的境外企业。按完整 PRD，界面语言基线包含中、英、西、印尼语及原国家语言，墨西哥的原国家语言映射西语；界面支持印尼语不代表接入印尼国家数据。

**基线成立条件。** 3人持续参与；11月20日前拿到可实施的只读检索与数据方案；真实名录、目录、身份关联、覆盖和字段许可到位；甲方能持续审核词典、文案和数据样本；部署及短信条件按节点提供。本计划不包含对甲方源库的任何写入或结构修改。

170人日为当前剩余工作估算，复核区间暂取152至188人日。该区间不包含从零建设未经评估的十亿级数据平台、长周期数据采购或外部审批等待；触发这些情形需重新估算，不能用188人日作为上限承诺。人日按所有参与角色的投入合计，不是每个人分别投入同样天数。

### 2.3 只有两人时的处理

2人比170人日基线缺约50人日，相当于2人团队额外约25个工作日，尚未考虑节假日和关键数据等待。不能同时承诺完整范围、同一截止日期和仅2人的稳定投入。

如11月13日仍未落实第三人的持续投入，应立即把进度标记为高风险，给项目负责人提供补人、等效外援、正式范围变更或日期调整的决策。当前确认的交付目标仍为完整 P0/P1/P2，未获变更前不删除 P2、B/C、语言或性能验收内容，也不把AI辅助视为额外一名全职开发者。

### 6.2 只读方案的决策顺序

先核查甲方是否已有符合要求的检索接口、只读数据集或服务，并用代表性条件验证性能、实体去重与统计口径。若无可用能力，再评估获许可的自有检索与汇总环境。两条路径都不允许本项目修改甲方源库，也不允许以最近几千条样本冒充全量检索。

若需要全量复制，应实测平均行大小、持续吞吐量、索引构建及更新成本。初始装载时间下界可按“核定记录数乘平均行大小再除持续吞吐量”估算，另加校验、索引构建与增量追平。仅凭行数无法承诺容量或完成天数；自有环境的许可、删除保留和更新方式必须先确定。

业务能力完整与数据覆盖范围分别确认。若甲方要求约3.1亿出口及13.84亿进口记录的全历史全文检索与聚合，必须在M1完成专项方案评审；不得在交付前悄悄缩小时间窗口或品类。

## 7 质量与验收计划

### 7.1 每个功能的完成定义

功能完成需同时具备正式API、真实或按规则声明缺失的数据、页面交互、服务端授权和所有者检查、错误状态、必要持久化、幂等与版本约束，以及对应测试证据。只有静态页面、演示数组或接口返回成功码，不满足完成定义。

每周完成演示和缺陷复盘；接口与数据逻辑至少由另一人复核。普通开发自测计入功能工作包；W10开始的集中容量用于跨模块场景、生产近似负载和甲方联合验收。

### 7.2 阶段验收重点

| 阶段 | 重点证据 | 不得替代的事实 |
| --- | --- | --- |
| P0 | 双登录及短信异常、角色并集、ABC正反例、企业去重、词典解释、四Tab、统计及排序口径 | 单条贸易记录不是企业主档；一次快查询不是P95；页面占位不是数据覆盖 |
| P1 | 两用户两条件隔离、收藏取消恢复、2至5家限制、证据撤销、固定报告及下载越权 | 原型收藏不等于持久化；报告不能在查看时拼装实时资料 |
| P2 | 存量账号兼容、审批并发、规则版本、四语、反馈重试、事件与业务对账 | 看板不补造历史；后台改状态不等于真实联系成功 |
| 发布 | 36用例、核定负载P95、安全回归、备份恢复、回滚、培训与运行手册 | 短时测试不证明月度99.5%已实现；没有许可不能以技术成功代替验收 |

性能基线在11月20日前与甲方确认，建议以10并发和不少于1000次可观察请求作为候选方案，覆盖HS、组合词、稀少与无结果、分页、冷热缓存、权限变化和故障。记录P50、P95、失败、排队、取消及源库负载；只在核定条件下判定首屏和详情主体P95不超过3秒。

P2事件在试点启用后通过真实操作采集，环境标记与生产分开。生产看板以实际生产采集起点为准，不把测试事件混入生产数据，不追填 P0/P1 行为历史。无结果率和转化率按 PRD 的完整成功及有结果等分母计算，失败与无覆盖单列。

当前开发环境按既有约定关闭搜索后端和前端等待超时，本计划不会直接恢复。上线前需完成成本预算、并发隔离、取消与终态设计，并由生产策略评审确定执行限制；无限等待不能替代性能验收和资源保护。

### 7.3 交付前冻结规则

1月15日起冻结新增功能；缺陷分级、影响范围与修复窗口在联合验收会上确认。阻断级及严重缺陷必须清零；其他遗留项如需接受，须有甲方书面结论、责任人和后续时间。不能把尚未满足的完整需求作为普通低级缺陷带过。

## 8 风险与调整机制

| 风险 | 触发信号 | 处理动作 |
| --- | --- | --- |
| 实际只有2人 | 11月13日仍无第三人投入计划 | 标红约50人日缺口，提出资源或交付约束决策；不承诺靠加班消化 |
| 检索体系不具备 | M1无可用查询能力或许可，代表性查询无法接近目标 | 升级数据专项评审，更新关键路径；不擅改甲方库、不缩成样本检索 |
| B/C和目录来源不足 | 没有真实经营产品证据、目的国或身份映射 | 甲方补充真实来源或形成明确验收变更，保持缺失而非造数据 |
| 规则与口径反复 | 企业身份、日期、覆盖和单位迟迟未核定 | 第一周建立决策清单；未核定不发布确定性指标，变更评估返工 |
| 短信或环境延迟 | 11月20日仍无法正式联调 | 尽早提供适配测试；生产依赖由甲方落实，不把固定码当正式交付 |
| 多语言审核拖延 | 12月18日未完成四语复核 | 提前分批审核，预留修正；任何语种缩减均需范围变更 |
| UAT后置 | 1月8日无验收人员和样本 | 组织按阶段预验收并升级协调，避免所有意见集中到最后两天 |

每周以实际完成工作、剩余投入和新风险重估，而不是只报告完成百分比。关键依赖延期超过两个工作日或影响下一里程碑时，当周形成影响说明、补救选项和决定记录。缓冲仅用于修复和小幅波动，不用于吸收未评估的数据平台建设或新增业务。
